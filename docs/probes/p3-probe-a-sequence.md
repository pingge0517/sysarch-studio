# 探针 A：时序图（Sequence 视图）结论

**结论：No-Go。时序图按规范 §6.1 降级为"只读导出 PNG"，不排入 P4。**

日期 2026-11-11。范围按规范 §6.1：只用 Sirius Web 2025.8.11 已有的能力，不写自研渲染器。探针代码不进主干，放在 `spike/p3-sequence-probe` 分支。

## 做了什么

- **元模型不改**：用状态机临时代替交互。非初始、非终止的状态当作生命线，迁移按列表顺序当作消息，trigger 当作消息名。
- **对齐的办法**：每条生命线是一个使用 Sirius 纵向列表布局（`ListLayoutStrategy`）的节点。每条生命线里放同样多的"格子"，每条消息一个，按消息顺序排列。这样第 *i* 个格子在每条生命线上都处于同一高度，消息 *i* 就从发送方的第 *i* 格连到接收方的第 *i* 格。
- **激活条**：生命线参与某条消息时，那一格画成激活条，否则画成虚线段。两种都用 SVG 图片节点。
- 后端只写了一个约 200 行的 Sirius 图描述，没有改前端。

## 对照判定标准

| 规范 §6.1 的 Go 条件 | 结果 |
|---|---|
| 3 条生命线 | ✔ 能画出，带虚线和激活条（图 1） |
| 6 条消息 | △ 消息都在，并且按顺序逐行对齐；但**连线大部分被挡住，只露出靠近箭头的一小段**（图 1、图 3）。自己发给自己的消息只画成一小段 |
| 拖动不丢布局 | ✔ 把一条生命线横向拖开再刷新，位置保留，所有消息仍然水平对齐（图 2）。对齐由列表布局保证，与手工布局无关 |

## 为什么判 No-Go

1. **消息看不清，问题在前端。** React Flow（Sirius Web 的画布）把连线画在节点下面，连线的大部分被生命线节点盖住。我们试过两种办法，都没有改善：把生命线设窄（Sirius 不允许节点比它的标题文字更窄）；把名字移到节点外（图 3）。连线的层级和自定义节点外观都由前端决定，后端描述控制不了。要让消息完整显示，就得写自己的前端节点或连线组件，也就是规范所说的"需要自研渲染"，同时也越过了"不替换渲染器"这条红线。
2. **编辑行为都得自己做。** 插入消息、调整消息顺序、自己发给自己的消息、组合片段（alt、loop）等，Sirius 都没有现成支持，都需要专门的工具和布局逻辑。即便显示问题解决了，这部分也远超两周。
3. **从 Sirius 自身看**：Sirius 桌面版有专门的 sequence 支持，Sirius Web 2025.8 没有；这个能力也不在已发布的 API 里。

## 正面发现（供以后参考）

- 列表布局加"每条消息一格"能稳定地让消息逐行对齐，拖动也不丢布局。如果将来 Sirius Web 提供"连线置于节点之上"或可配置的节点外观，可以从这里重启。
- 拖动后的布局由 Sirius 自己保存，与这个视图无关。

## 降级方案

时序图只读、导出 PNG。**已实现（2026-11-11）**：元模型 v1.4 新增 Interaction、Lifeline、Message；后端用纯 Java 画成 SVG 或 PNG（不依赖外部渲染器）；网页"时序图（只读）"负责查看和下载。详见 `../param-behavior.md` 第 5 节。
