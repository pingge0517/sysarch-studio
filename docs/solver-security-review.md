# 参数求解组件安全评审记录（P3 T4）

规范 P3 §3.4 指定求解脚本是 P3 唯一必须做安全评审的组件：它用 `exec` 执行一段表达式。本文记录威胁、防线、验证方式和剩余风险。

## 1. 被评审的对象

| 组件 | 位置 | 说明 |
|---|---|---|
| 求解脚本 | `solver/python_solver.py` | 规范 §3.4 原文（[COPY]，未改一字）：从标准输入读 JSON，`exec(body, {"__builtins__": {}}, local)`，用 SciPy `least_squares` 求解 |
| 远程求解服务 | `solver/http_server.py` | 只用 Python 标准库；每个请求起一个独立进程运行上面的脚本 |
| 后端适配层 | `backend/.../solver/` | 从模型生成要执行的代码，选择求解器，判定结果，回写参数 |

## 2. 威胁

1. 用户在约束块表达式里写入任意代码（`import os`、`open(...)`、`__import__`、属性链逃逸 `().__class__.__bases__`…），在服务器上执行。
2. 执行耗尽资源或长期不返回（死循环、超大幂运算）。
3. 求解进程访问网络或改写文件。
4. 求解服务被模型以外的人直接调用。

## 3. 防线（规范 §9："静态扫描 + 空命名空间 + 无网络只读容器，任一缺失则下线求解功能"）

| 层 | 做法 | 位置 |
|---|---|---|
| 1. 静态扫描 | 用户写的每一行必须是 `左边 = 右边`，只能出现本约束块的参数名、数字、`+ - * / ** ( )` 和空格。关键字（import、open、eval、exec、lambda、os、sys…）、下划线开头或双下划线、点、引号、方括号、逗号、冒号、分号以外的分隔都拒绝，并说明发现了什么。扫描通过的行被改写成生成的变量名 `v0`、`v1`…，脚本拿到的是后端生成的代码，不是用户原文 | `ExpressionSafety`、`SolveSystem` |
| 1'. 服务端再扫一次 | 远程服务只接受由名字、数字、运算符和换行组成的表达式，拒绝双下划线名字和关键字（422），因为它可能被模型以外的人调用 | `http_server.py` |
| 2. 空命名空间 | 脚本执行时 `__builtins__` 为空：`import`、`open`、`eval`、`__import__` 都不存在，执行即报错 | `python_solver.py`（规范原文） |
| 3. 独立进程 | 每次求解一个新进程：`python -I`（不读环境变量、不加载用户 site、不把当前目录放进路径），清空环境变量（Windows 只保留启动必需的 `SystemRoot`），工作目录是新建的临时目录，30 秒后连同子进程强制结束（504，不回写） | `PythonSolver` |
| 4. 容器 | 生产部署中求解在单独的 Pod 里：只读根文件系统，非 root，禁止提权，去掉全部 capabilities，`/tmp` 是 16 MiB 的内存盘；NetworkPolicy 只允许后端连入，出站全部禁止（连 DNS 都没有） | Helm `templates/solver.yaml`、`solver/Dockerfile` |

后端调用 `/solve` 需要登录，且角色要能建模（结果会写回模型），每次求解都记入审计日志（`SOLVE`）。

## 4. 验证

| 验证 | 结果 |
|---|---|
| `import os`、`__import__('os')`、`open('x')`、`eval('1')`、属性访问、方括号、引号、分号等 13 种写法 | 静态扫描全部拒绝（`SolveSystemTest`） |
| P3-AC-4：约束块表达式写成 `import os` 后调用求解 | 422，原因"不允许的关键字「import」"，求解器一次都没被调用（`SolveServiceTest`） |
| 绕过扫描，把 `import os`、`__import__`、写文件的 `open(...)`、`eval` 直接交给脚本 | 进程报错退出（空命名空间），目标文件没有被创建（`SolversTest`，真实 Python） |
| 远程服务收到 `import os` | 422，不起求解进程（`SolversTest` 启动真实的 `http_server.py`） |
| 超时 | 进程被强制结束，504，不回写（`SolversTest`） |

## 5. 剩余风险与约定

- **本机（Windows，无 Docker）没有第 4 层**：本地 `PythonSolver` 进程可以访问网络和当前用户能写的文件；它能执行的只是后端从参数名和算术生成的代码，所以第 1、2 层已经挡住了任意代码。生产部署必须使用 Helm 的求解 Pod（后端通过 `SYSARCH_SOLVER_REMOTE_URL` 调用），不要在后端容器里配置 `SYSARCH_SOLVER_PYTHON`。
- **资源**：表达式只有算术，但 `x ** 1000000` 这类运算仍可能占用 CPU 直到 30 秒超时；Pod 设置了 CPU 和内存上限。
- **脚本本身的缺陷**（规范原文，未修改）：脚本把表达式执行后目标变量的值当作残差，并在 `least_squares` 停在非零极小值时仍报告 `converged: true`。后端因此生成残差形式的代码，并按残差是否为零自行判定收敛；不收敛时不回写。
- 任一防线缺失时，按规范 §9 用 `SYSARCH_FEATURE_SOLVER=false` 下线求解（`/solve` 返回 503）。
