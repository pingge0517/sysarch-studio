## 1. 压测方法

脚本 `tests/perf/collab-load.mjs`（Node ≥ 22，无依赖），对着运行中的后端执行，后端以 dev 身份模式启动（`SYSARCH_AUTH_MODE=dev`），并开放监控接口（`MANAGEMENT_ENDPOINTS_WEB_EXPOSURE_INCLUDE=health,info,metrics`，仅压测时用环境变量打开，配置文件不变）。

- **30 个用户**（`user-1` 至 `user-30`）在一个演示模型的 LA 视图里各建一个自己的块，然后用 GraphQL `editLabel`（画布上的直接改名）不停改名：改一次，停顿 0.5 s ± 50%。
- **同元素冲突**：每次操作有 10% 的概率改共享块（演示模型的 4 个逻辑块）。做法与外壳的"编辑锁"页一致：先 `POST /locks` 申请锁，被占返回 423 就每 0.5 s 重试，直到持锁人释放；拿到锁后改名，停顿一下再释放。从第一次申请到拿到锁的时间记为"锁等待时长"。
- **周期性基线**：一个架构师每 2 分钟打一次基线。
- **采样**：每 15 s 读一次堆占用、GC 后存活数据、Hikari 连接池活动和排队连接数；另有监控进程每 5 分钟做一次线程转储（查死锁和 BLOCKED 线程），第三次起还强制一次完整 GC 并记录堆占用。
- **错误的定义**：任何 5xx 或意外的 4xx（等锁时的 423 是预期结果，不算）、GraphQL 错误、错误负载、网络失败、60 s 内拿不到锁、基线失败。结束时检查有没有丢失的修改：每个自己的块必须是用户最后一次写的名字，每个共享块必须是最后一个持锁人写的名字。

每次 30 分钟（另加 1 分钟预热，不计入），本机（Windows Server 2019，PostgreSQL 16 本地服务，后端单实例，JVM 默认堆）。

## 3. 内存：发现的三处增长

三处增长都是 Sirius Web 2025.8.11 自己保存的、按请求递增且从不释放的数据。修复都是新增的配置或处理器，没有改 Sirius 代码。

1. **每次输入一个监控计时器（第 1 次压测）**。Sirius 给编辑上下文的每个输入记一个计时器 `timer_processing_input`，标签里带输入自己的 UUID（`inputId`）；表示刷新的计时器 `timer_refresh_representation` 带 `changeDescription`。Micrometer 为每组不同的标签值保留一个计时器，直到 JVM 退出。压测后堆里有 109,303 个计时器，对应 109,886 次请求，占约 160 MB。这与监控接口是否开放无关，生产环境同样会发生，约每 10 万次编辑 160 MB。
   **修复**：`config.MetricsConfiguration` 用 `MeterFilter.ignoreTags("inputId", "changeDescription")` 去掉这两个标签，计时器按输入类型合并，测量数据不丢（`MetricsConfigurationTest`）。
2. **Spring Boot 的复合注册表（第 2 次压测）**。修复 1 只作用于 Spring Boot 复合注册表背后的注册表，复合注册表本身不应用过滤器，并且在过滤之前为每组标签各留一个计时器：第 2 次压测后仍有 104,079 个 `CompositeTimer`。
   **修复**：同一过滤器也加到每个复合注册表（在创建时，尚无计时器）和 Micrometer 的全局注册表上。验证：5 分钟、18,315 次请求后复合计时器 69 个；第 3 次压测中一直是 72 个。
3. **撤销历史（第 3 次压测）**。Sirius Web 为撤销/重做把每个输入的 EMF 修改记录存在编辑上下文的两个 `HashMap` 里（`EditingContext.inputId2change`、`inputId2RepresentationChanges`），从不修剪，项目关闭时才释放。第 3 次压测中，强制完整 GC 后的堆从 194 MB 涨到 226 MB（约每小时 100 MB），其中 68,496 个修改记录。项目删除后强制 GC，堆回到 108 MB，比开始前的 118 MB 还低，说明其他部分都已释放。
   **修复**：`config.UndoHistoryLimit`（输入后处理器）按先后顺序记录每个编辑上下文的输入，超过 `sysarch.undo.max-steps`（默认 500）就从两个映射里删除最旧的。撤销已删除的步骤时 Sirius 先判空、什么也不做，所以撤销仍能回退最近 500 步（`UndoHistoryLimitTest`）。
   **未验证**：验证这项修复的第 4 次压测按要求在开始约 6 分钟时停止，还没有内存采样。
