# 参数图、行为视图与 XMI（P3 使用说明）

本文说明 P3 新增的功能：参数图与外接求解、状态机图、活动图、用例图、XMI 导出与导入。最后一节是**对外必须说明的三条限制**。

## 1. 参数图与求解

### 参数图

在约束块上选择 **参数图（Parametric）**：
- 每个约束块是一个方框，参数画在方框边上，方框里列出"方向 名称 : 单位"；
- 绑定是参数之间的连线，**只能绑定单位相同的参数**，不做单位换算；单位不同的绑定在拖放时就会被拒，已有绑定的单位被改得不一致时，保存会撤销这次修改；
- 单位必须在白名单内：m、kg、s、A、K、mol、cd、W、V、Hz、N、Pa、J、C、rad、1、mm、cm、km、g、ms、us、kHz、MHz。

### 求解

`POST /api/v1/solve`：

```json
{"projectId": "…", "constraintBlockIds": ["CB-1", "CB-2"], "solver": "python",
 "inputs": {"P_in": 100, "eff": 0.9}, "targets": ["P_out"], "options": {"tolerance": 1e-6}}
```

- 参数可以用元素 id 指定；名称在所选约束块里唯一时，也可以用名称。
- 方程组在求解之前先检查一遍，有以下任一问题就直接返回 422 并说明原因，不调用求解器：
  - 单位不在白名单内；
  - **超定**（方程多于未知量）或**欠定**（方程少于未知量）；
  - 表达式里出现了算式以外的东西。表达式只能写"左边 = 右边"，只能用参数名、数字和 `+ - * / ** ( )`。
- 求解成功（残差为零）时，结果写回参数的 `defaultValue`，参数图上显示为"名称 = 值"。没有收敛就返回 `converged: false`，不写回任何值。
- 30 秒未完成返回 504，不写回。别人锁着要写回的参数时返回 423，同样不写回。
- 求解器有三种：`python`（SciPy）、`remote`（独立的求解服务）、`modelica`（OpenModelica）。没有配置的求解器返回 503。

## 2. 行为视图（只建模，不执行）

| 视图 | 在哪个元素上打开 | 画法 |
|---|---|---|
| 状态机图 | 状态机 | 初始态是实心圆，终止态是圆环套实心圆，状态是圆角矩形（显示 entry/do/exit）；迁移标签为 `触发[守卫]/效果`，空的部分不显示 |
| 活动图 | 活动 | 动作是矩形，表达式写在名称下方；判定是菱形；控制流用实线，对象流用虚线 |
| 用例图 | 用例 | 用例是椭圆，参与者是火柴人，关联是不带箭头的实线（"关联参与者"只是在两者之间建立引用） |

**大图分区（规范 §9）**：行为图一次最多画 200 个节点。超过时，按迁移/流/关联广度优先排序（相邻的元素尽量在同一分区），每 200 个为一个分区，一次只画一个分区。图框标题会写明当前位置，例如"分区 2/5：第 201–400 个（共 1000 个），跨分区连线 37 条未画出"。用工具面板里的"上一分区/下一分区"切换。分区只影响显示，不改模型；跨分区的连线不画，只计数。

实测依据（本机，2026-11-11）：
- 服务端渲染 2000 个状态只需 0.2 秒；
- 不分区时，Sirius 前端打开 1000 个状态用了 6.3 秒，之后页面失去响应；500 个状态时，每次缩放要 1.9 秒；
- 分区后，1000 个状态的图重新打开约 1.4 秒（首次打开含自动布局约 3.3 秒），每次缩放约 1.7 秒（这是 Sirius 画布本身的开销）。

静态检查在一致性报告和校验面板里显示：
- **R7**：初始态不是恰好一个
- **R8**：存在不可达的状态
- **R9**：存在死迁移
- **R10**：CALL 动作没有表达式

## 3. XMI

- **导出**：`POST /api/v1/export/xmi`，输出 XMI 2.5.1 / UML 2.5.1 / SysML 1.6。详见 `xmi-export.md`。
- **导入**：`POST /api/v1/imports/xmi`，也可以在网页"导入"里把格式选为 XMI。只接受本工具导出的 XMI，或结构极简的 Cameo 导出；其他内容整批失败，并逐个列出。

## 4. 对外限制说明（三条，必须向用户和客户明确）

1. **XMI 往返不保证分层无损。** 分层（layer）和自定义构造型在标准 XMI 中没有对应项，导出时写在 `xmi:Extension` 中，标准工具看不到，也不会保留。从 Cameo 等工具导回时，分层不能还原，元素会放在默认层。本工具只保证"元素与关系不丢"。需要连分层一起无损交换时，请用 SysML v2 文本导出。
2. **参数求解依赖外部后端。** 求解不是本工具自研的能力，而是调用外接的 Python（SciPy）、Modelica（OpenModelica）或独立的求解服务。没有配置求解后端时不能求解，接口返回 503。求解结果的正确性取决于外部求解器，本工具只负责检查方程组、调用求解器、判定残差和写回结果。对外的统一说法是"外接 Python/Modelica 求解"。
3. **行为图不执行。** 状态机图、活动图、用例图只用于建模和静态检查（R7–R10），不做仿真，不执行状态迁移或动作，也不支持 fUML 执行语义。如果验收要求模型可执行，应考虑 Cameo 等专业工具（规范 §10.2）。

另外：**时序图只能只读查看，不能在画布上编辑**。探针 A 的结论是 No-Go（见 `probes/p3-probe-a-sequence.md`），因此按规范降级为只读图片，见第 5 节。

## 5. 时序图（只读）

探针 A 判定不能在 Sirius 画布上做可用的时序图，按规范 §6.1 降级为只读图片：

- **建模**：在 Sirius 的模型浏览器里新建交互（Interaction，文档根元素），在交互下新建生命线（Lifeline，可用 `represents` 指向它代表的块、部件或参与者）和消息（Message，按时间顺序排列；`sender`、`receiver` 为生命线；`kind` 可选 SYNC、ASYNC、REPLY）。
- **查看**：网页"时序图（只读）"列出项目里的交互并显示成图，可以下载 SVG 或 PNG。也可以直接调用接口：`GET /api/v1/projects/{项目}/interactions`，以及 `…/interactions/{id}/sequence.svg` 或 `.png`。
- **画法**：
  - 用 UML 的 sd 框；
  - 生命线头部写"名称 : 代表的元素"，下面是虚线；
  - 同步消息为实线加实心箭头，异步消息为实线加开放箭头，返回消息为虚线；
  - 发给自己的消息画成小环；
  - 生命线参与消息的位置画激活条，连续的合并成一段；
  - 缺少发送方或接收方的消息不画，而是在图下列出。
- **导出与导入**：交互会随 SysML v2 文本和 XMI 一起导出，也能从中导入，往返不丢信息：
  - SysML v2 中表示为 `occurrence def`，生命线是其中的 `part`（代表某个块时，类型就是这个块），消息写成 `message … from … to …`，时间顺序用 `first … then …` 表达；
  - XMI 中表示为 UML 的 Interaction：生命线、按时间顺序排列的消息发送/接收事件、带 messageSort 的消息；
  - SysON 读入 SysML v2 文本时没有报错，消息两端都能解析到对应的生命线；Eclipse UML2 校验 XMI 也没有发现问题。
- **限制**：图片只读；生命线代表的若不是块（例如部件或参与者），这一信息只存在于 SysArch 自己的注释或扩展里，其他工具看不到。
